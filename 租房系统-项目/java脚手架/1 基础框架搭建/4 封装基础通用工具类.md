泛型擦除问题

```
泛型擦除是什么？

Java中的泛型擦除（Type Erasure）是指Java编译器在编译泛型代码时，会移除泛型类型参数的相关
信息，使得⽣成的字节码中不包含泛型类型信息。这使得Java泛型在运⾏时（Runtime）表现为原始
类型（Raw Type）

泛型擦除为什么出现？

向后兼容：Java泛型是在Java 5中引⼊的，为了让新版本的代码与旧版本的Java代码兼容，泛型擦
除是⼀种简单有效的实现⽅式。因为泛型信息在编译时已经被擦除了，所以旧版本的JVM可以运⾏
包含泛型的新代码

类型安全：尽管泛型信息在编译时被擦除，但Java编译器在编译时会进⾏类型检查，确保泛型的使
⽤是安全的。这意味着你可以在编译时发现类型错误，⽽不是在运⾏时。

避免性能开销：如果JVM需要在运⾏时维护泛型类型信息，那么这将会引⼊额外的性能开销。泛型
擦除避免了这种开销，因为所有的类型信息在编译时就已经确定了

泛型擦除解决办法

对于常⻅的Collection如 List、Map 中包含泛型，需要先反序列化Collection类型为泛型的Collection
Type。
如果是ArrayList<YourBean>那么使⽤ObjectMapper 的
getTypeFactory().constructParametricType(collectionClass, YourBean.class); 如果是
HashMap<String,YourBean>那么 ObjectMapper 的
getTypeFactory().constructMapType(HashMap.class,String.class, YourBean.class);
```

### Jackson核心配置

## 一、反序列化相关配置

| 配置项 | 作用 |
|---|---|
| `.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false)` | 反序列化时忽略 Java 类中未定义的 JSON 属性，避免因多余字段导致失败，提高兼容性。 |
| `.configure(DeserializationFeature.FAIL_ON_INVALID_SUBTYPE, false)` | 反序列化时放宽类型标识不匹配限制。即使 JSON 中类型信息与期望 Java 类型层次不完全匹配，也尝试继续反序列化，提高容错性。 |

## 二、序列化相关配置

| 配置项 | 作用 |
|---|---|
| `.configure(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS, false)` | 日期序列化时不使用时间戳，而按后续配置的日期格式输出，增强可读性。 |
| `.configure(SerializationFeature.FAIL_ON_EMPTY_BEANS, false)` | 允许序列化没有属性值的空对象，通常生成空 JSON 对象 `{}`，避免序列化失败。 |
| `.configure(SerializationFeature.WRITE_DATE_KEYS_AS_TIMESTAMPS, false)` | 当 Date 作为 Map 键等日期键结构时，不使用时间戳形式，而按日期格式统一处理。默认值为 `false`。 |
| `.serializationInclusion(JsonInclude.Include.NON_NULL)` | 序列化时只包含非空值，忽略 `null` 字段。 |

## 三、注解与全局规则

| 配置项 | 作用 |
|---|---|
| `.configure(MapperFeature.USE_ANNOTATIONS, false)` | 不依赖 Jackson 注解定制序列化/反序列化行为，更多依据全局配置控制，适合统一管理 JSON 规则、减少注解复杂度。 |

## 四、日期时间模块与格式

### 1. 注册 Java 时间模块
```java
addModule(new JavaTimeModule())
```
- 序列化 `LocalDateTime`、`LocalDate` 的必要配置。
- 由 `jackson-datatype-jsr310` 实现。

### 2. 设置默认日期格式
```java
.defaultDateFormat(new SimpleDateFormat(CommonConstants.STANDARD_FORMAT))
```
- 统一日期格式为：`yyyy-MM-dd HH:mm:ss`。

### 3. 自定义 LocalDateTime 序列化/反序列化格式
```java
.addModule(new SimpleModule()
    .addSerializer(
        LocalDateTime.class,
        new LocalDateTimeSerializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"))
    ) // 序列化时起作用
    .addDeserializer(
        LocalDateTime.class,
        new LocalDateTimeDeserializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"))
    ) // 反序列化时起作用
)
```
- 序列化时：将 `LocalDateTime` 等时间类型转换为指定格式的 JSON 字符串。
- 反序列化时：将指定格式的时间字符串转换为 `LocalDateTime` 等时间类型。
- 注意：示例代码针对 `LocalDateTime`；原文说明该思路适用于 `LocalDateTime` 和 `LocalDate` 时间类型。

## 五、整体配置目的总结

1. **提高反序列化容错性**：忽略未知属性、放宽子类型匹配限制。
2. **提高序列化稳定性**：允许空对象序列化、忽略 `null` 值。
3. **统一日期时间格式**：不使用时间戳，统一输出 `yyyy-MM-dd HH:mm:ss`。
4. **支持 Java 8 时间类型**：注册 `JavaTimeModule`，并自定义 `LocalDateTime` 格式。
5. **减少注解依赖**：通过 `USE_ANNOTATIONS=false` 更多使用全局配置统一管理 JSON 行为。
