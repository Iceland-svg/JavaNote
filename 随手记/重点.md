针对Java后端面试，尤其是大厂或中高级岗位，**“广度决定下限，深度决定上限”**。面试官最看重的不是“你会多少框架”，而是**“你如何解决复杂问题和应对高并发场景”**。

基于当前（2026年）的面试趋势，我把需要着重关注的知识点分为**五个核心层级**，并标注了具体的深度要求：

### 第一层级：Java语言底层与并发（决定你是否能过“硬核”一面）

这是必考且扣分最狠的板块，不能停留在“会用”层面。

- **JVM（重中之重）**：除了常见的类加载、内存模型，必须**深挖**垃圾回收（GC）。不仅要说出CMS和G1的区别，更要理解**ZGC**（2026年JDK 17/21已成标配）的核心原理（读屏障、染色指针）。必须能结合GC日志进行**性能调优实战**（如调整新生代/老年代比例、元空间大小）。
- **并发编程（JUC）**：**AQS（抽象队列同步器）**是灵魂，必须手写推导ReentrantLock的非公平锁加锁流程。重点掌握**CompletableFuture**的异步编排（超时控制、任务组合），以及**线程池**的核心参数动态调整策略（拒绝策略落地，如Dubbo的线程池隔离）。

### 第二层级：数据库（MySQL + 索引调优）（决定你的“写SQL”能力）

面试官通常会用一个慢查询SQL作为切入点，一路问到架构层面。

- **索引与执行计划**：重点掌握**覆盖索引**、**回表**、**索引下推（ICP）**。必须能根据`EXPLAIN`分析`Using filesort`和`Using temporary`产生的原因，并给出索引优化的具体方案（如最左前缀法则的变形应用）。
- **事务与锁**：**MVCC（多版本并发控制）**原理（Read View可见性算法）是必杀技。要区分**当前读**与**快照读**，并深入理解间隙锁（Gap Lock）如何解决幻读，以及在RR（可重复读）级别下如何避免死锁（如调整加锁顺序）。

### 第三层级：缓存（Redis）（决定高并发场景下的“读”能力）

Redis几乎是大厂面试的“第二语言”，重点不在数据结构，而在**稳定性**。

- **底层结构**：跳表（Zset）的插入流程、SDS（简单动态字符串）的内存预分配机制。
- **高可用与持久化**：RDB和AOF的混合持久化原理，以及**主从复制**的全量/增量同步断点续传逻辑。
- **三大核心难题（必考）**：**缓存穿透**（布隆过滤器进阶版）、**缓存击穿**（互斥锁 vs 逻辑过期）、**缓存雪崩**。此外，**Redis分布式锁**（Redisson看门狗机制）的锁续期和可重入性，以及**缓存与数据库双写一致性**（先删缓存还是先更新DB？延时双删的缺陷及Canal订阅方案）。

### 第四层级：微服务与分布式（Spring Cloud + 消息队列）（决定架构视野）

Spring Boot的自动装配原理是基础，重点看**Spring Cloud 2023+**（基于Spring Cloud Alibaba）。

- **服务治理**：Nacos的注册中心（AP/CP模式切换）与配置中心动态刷新原理。**Feign**的底层通信（负载均衡策略、重试机制与业务幂等的冲突处理）。
- **消息队列（RocketMQ/Kafka）**：重点在**消息可靠性**（Producer重试、Broker同步刷盘、Consumer手动提交）。必须掌握**顺序消费**的实现方式（MessageQueue选择器）和**消息积压**的紧急扩容解决方案。
- **分布式事务**：掌握**TCC**和**Saga**模式的适用场景，以及Seata AT模式的二阶段提交底层日志回滚机制（Undo Log）。

### 第五层级：系统架构设计（开放性场景题）（决定薪资上限）

这是中高级面试的“分水岭”，通常以一个业务场景（如“设计一个秒杀系统”或“设计一个短链接服务”）展开。

- **高可用三把斧**：**限流**（Sentinel的滑动窗口/漏桶算法，细化到接口级别的降级规则）、**熔断**（慢调用比例熔断后的半开状态探测）、**降级**（本地缓存降级兜底数据）。
- **幂等性设计**：基于**Redis原子操作** + **数据库唯一约束** + **状态机**的终极防重方案。
- **数据一致性**：分布式场景下的**最终一致性**方案（如本地消息表+任务调度，或者利用RocketMQ的事务消息反查机制）。

**给2026年面试者的特别提点（加分项）：**

1. **云原生与GraalVM**：如果面试官问及Spring Boot 3.x，务必提到**AOT（提前编译）**和**GraalVM原生镜像**带来的启动速度提升，这是当前微服务降本增效的热点。
2. **Arthas（阿尔萨斯）**：能说出几个线上问题排查的Arthas实战命令（如`trace`、`watch`、`jad`），会极大提升面试官的好感度。
3. **算法**：后端面试算法不用刷太偏，重点死磕**二叉树**（层序遍历变种）、**LRU缓存设计**（手写LinkedHashMap版）和**TopK问题**（堆实现），这些与后端业务耦合度最高。
