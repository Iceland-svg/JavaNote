```java
    private static Object locker = new Object();

        Thread t1 = new Thread(()->{

                    count++;  
                }  
        });

                }

        t2.start();
```

```java
public class Test3 {  
    private static int count = 0;  
    private static Object locker = new Object();  
    public static void main(String[] args) throws InterruptedException{  
        //如过把synchronized放到外面  
        //那么t1获取到锁之后，就会一直执行到for循环结束  
        //结束后释放锁，t2此时才获取到了锁，这是就失去了并发的意义  
        Thread t1 = new Thread(()->{  
            synchronized (locker){

        t1.join();

    }  
}
```

## 3 锁是什么?

锁的作用就是把若干个操作打包成一个，让其符合==原子性==

如果锁被占用，必须等待第一个锁解锁，这个时候第二个对象就处于阻塞状态，这时就产生了锁竞争，锁冲突

### 3.1时间线解释为什么运行结果对了

实际上是，对count加锁了，他的三条指令必须执行完，才能执行另一个线程里的count，这是其实就是从穿插执行变为串行执行、

如果把synchronized放到外面，那么就是给整个线程加锁，必须让整个线程执行完，另一个线程才能从阻塞状态开始执行

## 7 如何避免死锁问题?

### 首先要理解死锁的四个必要条件

（1）锁本身是互斥的

（2）锁不可被抢占，线程1拿到锁，线程2想要这个锁必须要阻塞等待

（3）请求和保持 线程在拿到第一把锁的情况下，不释放第一把所，而去请求第二把锁——==车钥匙锁家里了，家里钥匙锁车里了==

（4）循环等待，等待锁的释放构成循环

### 解决方案
（1）让锁先释放再去拿另一个锁
（2）打破循环等待，约定加多个锁的时候，必须按照一定的顺序来加锁locker1,locker2

### 9.2 wait做了什么?

阻塞当前代码，同时释放该线程的锁，满足一定条件时被唤醒，尝试重新获取这个锁

wait阻塞的两个阶段

1 WATING状态的阻塞，通过wait等待其他线程的通知

2 BLOCKED的阻塞，收到通知之后就会尝试重新获取锁，很可能遇到锁竞争

## 10 面试题——sleep和wait的区别是什么？

1 设计理念不一样
wait设计出来就是为了提前唤醒的，设置等待时间上线，只是后手计划
sleep设计出来是为了到特定时间唤醒，到时间唤醒的，虽然也可以通过interrupt（）方法提前唤醒，但是这样的唤醒是会产生异常的（程序不符合预期）

2 wait需要搭配锁来使用，并且阻塞的同时会释放锁
sleep放到synchronized内部时，则是不会释放锁，一直带着锁阻塞

## 11.4 指令重排序引起的线程安全问题

指令重排序是编译器的一种优化策略，为的是调整指令的顺序来优化程序执行更快

但是，在这种优化策略下的多线程，执行new操作时，（主要有三个步骤，申请空间，初始化，把内存地址保存到引用变量中）
优化之后，先申请空间，在存地址到引用变量，如果在申请空间和存地址到引用变量之后调度到另一个线程，这时如果这个线程调get，拿到实例，使用时，会发现该实例并没有初始化

*这里最关键的是，读操作是不需要锁的，假如另一个线程检查instance!=null后，会直接返回了，返回的instance由于指令重排序初始化可能不完整，调get操作得到的就是不完整的instance，锁不能阻止其他变量读取共享变量!!!这个变量是共享的虽然，锁让变量只能让第一个线程来new*

### 11.5 解决方案
在变量前加上volatile，让这个变量在读写操作时不要触发优化
