## 1 阻塞队列特征
（1）线程安全
（2）带有阻塞功能
-如果队列为空，尝试出队列，就会触发阻塞知道队列不为空
-如果队列为满，尝试入队列，就会触发阻塞，知道队列不为满

---

## 2 生产者消费模型（是分布式系统的一种重要设计模式）

(1) 减少资源锁竞争，提高效率
(2) 跟好的做到模块之间的解耦
(3) 削峰填谷

---

## 3 分布式系统

服务器开发通常是开发一组服务器程序

### 阻塞队列在分布式系统中的作用是什么?

(1) 削峰填谷，请求多的时候会阻塞，防止超过资源提供上限，导致服务器挂了
(2) 解耦合

### 缺点：
系统更加复杂，引入的队列层数太多，会增加网络通信的开销

#### 生产者消费者模式运用

```java
public class useOfBlockingQueue {  
    public static void main(String[] args)  {  
        //new一个阻塞队列  
        BlockingQueue<String> queue = new LinkedBlockingQueue(1000);  
        //生产者  
        Thread producer = new Thread(()->{  
            int count = 0;  
            while (true){  
                try {  
                    queue.put(""+count);  
                    System.out.println("生产了一个元素"+count);  
                    count++;  
                    Thread.sleep(1000);  
                } catch (InterruptedException e) {  
                    e.printStackTrace();  
                }  
            }  
        });  
        //消费者  
        Thread consumer = new Thread(()->{  
            while (true){  
                try {  
                    String elem = queue.take();  
                    System.out.println("消费了一个元素"+elem);  
                    Thread.sleep(1000);  
                } catch (InterruptedException e) {  
                    e.printStackTrace();  
                }  
            }  
        });  
        producer.start();  
        consumer.start();  
    }  
}
```
#### 自实现阻塞队列

```java
public class MyBlockingQueue {private static Object locker = new Object();  
    private String[] array = null;  
    private int head = 0;  
    private int tail = 0;  
    private int size = 0;  
  
    //这种构造更为常用，是仅仅给成员变量开辟空间  
    public MyBlockingQueue(int capacity) {  
        array = new String[capacity];  
    }  
  
    //这种构造是把传过来的字符串数组赋给调用对象  
//    public MyBlockingQueue(String[] array) {  
//        this.array = array;  
//    }  
    //入队列  
    public void put(String elem) throws InterruptedException{  
        //  
        synchronized (locker){  
            //不排除有其他代码在唤醒之后 条件任然成立，所以利用while二次判断  
            while (size >= array.length){  
                locker.wait();  
            }  
            array[tail] = elem;  
            tail++;  
            if(tail >= array.length){  
                tail = 0;  
            }  
            size++;  
            //唤醒take中的wait  
            locker.notify();  
        }  
    }  
  
    //  
    //出队列  
    public String tack() throws InterruptedException{  
        synchronized (locker){  
            while(size == 0){  
                locker.wait();  
            }  
            String result = array[head];  
            head++;  
            if(head >= array.length){  
                head = 0;  
            }  
            size--;  
            //唤醒put中的阻塞  
            locker.notify();  
            return result;  
        }  
    }  
}
```
#### 为什么把if改为while?

这里的使用while其实是==**二次确认**==，不排除如果存在其他的代码，让if确认进入wait阻塞后，队列仍然是满的，程序如果接着往下执行就违背了会出现错误
所以官方建议利用while，在被唤醒之后，由于循环机制，再次确认是否满了
