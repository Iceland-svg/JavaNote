泛型擦除问题

```
泛型擦除是什么？

Java中的泛型擦除（Type Erasure）是指Java编译器在编译泛型代码时，会移除泛型类型参数的相关
信息，使得⽣成的字节码中不包含泛型类型信息。这使得Java泛型在运⾏时（Runtime）表现为原始
类型（Raw Type）

泛型擦除为什么出现？

向后兼容：Java泛型是在Java 5中引⼊的，为了让新版本的代码与旧版本的Java代码兼容，泛型擦
除是⼀种简单有效的实现⽅式。因为泛型信息在编译时已经被擦除了，所以旧版本的JVM可以运⾏
包含泛型的新代码

类型安全：尽管泛型信息在编译时被擦除，但Java编译器在编译时会进⾏类型检查，确保泛型的使
⽤是安全的。这意味着你可以在编译时发现类型错误，⽽不是在运⾏时。

避免性能开销：如果JVM需要在运⾏时维护泛型类型信息，那么这将会引⼊额外的性能开销。泛型
擦除避免了这种开销，因为所有的类型信息在编译时就已经确定了

泛型擦除解决办法

对于常⻅的Collection如 List、Map 中包含泛型，需要先反序列化Collection类型为泛型的Collection
Type。
如果是ArrayList<YourBean>那么使⽤ObjectMapper 的
getTypeFactory().constructParametricType(collectionClass, YourBean.class); 如果是
HashMap<String,YourBean>那么 ObjectMapper 的
getTypeFactory().constructMapType(HashMap.class,String.class, YourBean.class);
```

### Jackson核心配置

#### 1. 反序列化容错

- `FAIL_ON_UNKNOWN_PROPERTIES=false`：忽略 JSON 中多余属性。
  （默认 `true` 会抛 `UnrecognizedPropertyException`；代价是字段拼错、上游改名都静默变 `null`，建议测试环境保持 `true` 做契约校验）
- `FAIL_ON_INVALID_SUBTYPE=false`：类型标识不匹配时尽量继续反序列化。
  （默认 `true` 抛 `InvalidTypeIdException`；关掉后是字段直接为 `null` 而非报错，下游容易 NPE。切勿开 `activateDefaultTyping`，多态反序列化是漏洞重灾区）

#### 2. 序列化容错

- `WRITE_DATES_AS_TIMESTAMPS=false`：日期不用时间戳，按格式输出。
  （默认 `true` 时 `Date` 输出 `1730084727000`、`LocalDateTime` 输出 `[2026,10,28,...]`；关掉后变 ISO，**但带 `T`**，不是 `yyyy-MM-dd HH:mm:ss`）
- `FAIL_ON_EMPTY_BEANS=false`：允许空对象序列化为 `{}`。
  （默认 `true` 抛 `No serializer found`；触发原因多是 Lombok 没生成 getter 或返回了代理对象——这个开关会把这类真 bug 藏起来）
- `WRITE_DATE_KEYS_AS_TIMESTAMPS=false`：日期作为键时也不用时间戳，默认已是 `false`。
  （只管 Map 的 key，不管 value；**2.16 才引入**，低版本写这行编译不过）
- `serializationInclusion(NON_NULL)`：只序列化非空值。
  （默认 `ALWAYS`；只作用于 Bean 属性，`Map`/`List` 里的 null 不会清；也不等于 `NON_EMPTY`，`""`、`[]` 仍会输出）

#### 3. 注解控制

- `USE_ANNOTATIONS=false`：不依赖 Jackson 注解，更多用全局配置统一管理。
  （关掉的是**全部**注解：`@JsonProperty` 重命名失效、`@JsonIgnore` 失效——密码类字段会直接出现在响应里，且不报错。除非全项目统一约定，否则别关）

#### 4. 日期时间配置

- `addModule(new JavaTimeModule())`：支持 `LocalDateTime`、`LocalDate`，需 `jackson-datatype-jsr310`。
  （2.12+ 不注册直接抛 `InvalidDefinitionException`；Spring Boot 会自动装，但自己 `new ObjectMapper()` 的工具类不会）
- `defaultDateFormat(...)`：统一日期格式为 `yyyy-MM-dd HH:mm:ss`。
  （**只对 `java.util.Date` 生效，对 `LocalDateTime` 完全无效**，这是最常见的误解；另外 Jackson 默认时区是 UTC，不设 `Asia/Shanghai` 会少 8 小时）
- `SimpleModule` 自定义 `LocalDateTime`：
  （必须 `addModule` 在 `JavaTimeModule` **之后**——后注册优先级更高，顺序反了会"看起来没生效"）
  - 序列化：`LocalDateTime` → `yyyy-MM-dd HH:mm:ss`
  - 反序列化：指定格式字符串 → `LocalDateTime`（用 `DateTimeFormatter`，并自己处理 `null`/空串，否则 `""` 抛异常）

#### 核心目的：

**提高反序列化容错、避免序列化失败、统一日期格式、支持 Java 8 时间类型、减少注解依赖。**

（补充一句：每个 `FAIL_ON_*=false` 本质都是把"报错"换成"静默"，所以生产宽松、测试严格才是正确用法）
