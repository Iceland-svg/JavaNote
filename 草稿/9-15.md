下面是一套可以直接配合 **Claude Code** 使用的提示词。建议你先在空目录中启动 Claude Code，然后把下面的“项目宪法”保存为 `CLAUDE.md`，再按阶段复制对应提示词。每完成一个阶段，让它运行测试、提交 Git，再进入下一阶段。

## 一、项目宪法：保存为 `CLAUDE.md`

```markdown
# 项目：VoxelGame（受 Minecraft 启发的 Java 体素游戏）

## 目标
用 Java 从零开发一个学习用途的体素沙盒游戏，模仿 Minecraft Java 版的核心玩法与架构：
- 第一人称移动、破坏/放置方块、区块加载、世界生成、简单物品栏、存档。
- 仅用于学习，不复制 Minecraft 的代码、材质、音效、名称、商标或任何受版权保护的资产。
- 项目名使用 VoxelGame，包名使用 com.example.voxel。

## 技术栈
- Java 21
- Gradle Kotlin DSL
- LWJGL 3（GLFW、OpenGL、stb、joml）
- OpenGL 3.3 Core Profile，后续可考虑 Vulkan
- JOML 数学库
- SLF4J + Logback 日志
- JUnit 5 测试
- Git 版本控制

## 架构原则
- 逻辑上区分客户端、服务端、公共代码。先做单机内置服务器。
- 包结构：
  - com.example.voxel.client
  - com.example.voxel.server
  - com.example.voxel.common
  - com.example.voxel.world
  - com.example.voxel.render
  - com.example.voxel.math
  - com.example.voxel.util
- 区块大小 16x16x256，后续可调整。
- 使用组件式实体或轻量 ECS。
- 数据驱动：方块、配方等尽量用 JSON 定义。
- 渲染使用 VAO/VBO/EBO、着色器、纹理图集。
- 区块生成与网格构建使用工作线程，避免阻塞主线程。

## 编码规范
- 每个类单一职责，避免 God Class。
- 公共 API 写 Javadoc。
- 新功能必须有单元测试。
- 使用 SLF4J 记录日志，禁止 System.out.println。
- 提交信息使用：feat、fix、refactor、test、docs、chore。

## 常用命令
- ./gradlew run
- ./gradlew test
- ./gradlew build

## 工作方式
- 每次只做一个阶段或一个垂直切片。
- 开始前先输出计划、要修改的文件、验收标准。
- 实现后运行测试和游戏，失败则修复到通过。
- 最后总结变更、遗留问题和下一步。
- 不要一次性生成大量未经验证的代码。
```

## 二、分阶段提示词

### 阶段 0：需求澄清与规划

```text
请先阅读 CLAUDE.md。我们要开发一个受 Minecraft 启发的 Java 体素游戏，仅用于学习。

现在不要写代码。请完成：
1. 确认最小可行版本（MVP）的功能范围。
2. 列出前 10 个开发里程碑，按依赖关系排序。
3. 为每个里程碑定义可验证的验收标准。
4. 指出最大技术风险，例如 OpenGL、区块线程、存档格式、性能。
5. 给出推荐的包结构和核心类草图。

输出 Markdown，等我确认后再进入阶段 1。
```

### 阶段 1：项目初始化与窗口

```text
进入阶段 1：初始化 Gradle 项目。

要求：
- Java 21，Gradle Kotlin DSL。
- 添加 LWJGL BOM、GLFW、OpenGL、stb、JOML、SLF4J、JUnit 5。
- 创建主类 com.example.voxel.Main。
- 使用 GLFW 打开 1280x720 窗口，标题 VoxelGame，OpenGL 3.3 Core。
- 实现游戏循环：计算 deltaTime，调用 update/render，ESC 关闭。
- 清屏为天蓝色。
- 添加 ./gradlew run 和 ./gradlew test。
- 写 README.md，说明运行方式。
- 添加 .gitignore。

完成后运行 ./gradlew test 和 ./gradlew run，确保无错误。提交 Git。
```

### 阶段 2：渲染第一个立方体与相机

```text
进入阶段 2：渲染一个带纹理的立方体。

要求：
- 使用 OpenGL 3.3 Core，VAO/VBO/EBO，编写顶点和片段着色器。
- 使用 JOML 实现透视投影、视图矩阵、模型矩阵。
- 实现第一人称相机：WASD 移动，鼠标视角，滚轮缩放，ESC 释放鼠标。
- 创建立方体网格，支持位置、法线、UV。
- 创建一个简单纹理或纯色面，先不依赖外部版权素材。
- 代码分到 render、camera、shader 包。
- 为相机矩阵和移动逻辑写单元测试。

完成后运行游戏验证，提交 Git。
```

### 阶段 3：区块与网格生成

```text
进入阶段 3：实现体素区块。

要求：
- 定义 Block 类型注册表，至少包括 AIR、STONE、DIRT、GRASS、WOOD、LEAVES。
- 实现 Chunk 16x16x256，存储方块 ID。
- 实现 ChunkMeshBuilder：只生成暴露面，输出顶点位置、法线、UV、纹理层。
- 创建纹理图集，至少 16x16，支持 mipmap。
- 渲染一个区块，并在其中放置几种方块。
- 单元测试面剔除逻辑，确保内部面不生成。

完成后运行游戏验证，提交 Git。
```

### 阶段 4：世界与区块管理

```text
进入阶段 4：实现 World 和 ChunkManager。

要求：
- 无限世界，按玩家位置加载/卸载区块。
- 异步区块生成和网格构建，使用线程池。
- 世界生成：基于 Perlin/Simplex 噪声的地形，高度图，草/泥土/石头，简单树木。
- 渲染距离可配置。
- 避免主线程卡顿，区块数据线程安全。
- 测试世界生成的确定性：相同种子生成相同地形。

完成后运行游戏验证，提交 Git。
```

### 阶段 5：玩家物理与碰撞

```text
进入阶段 5：实现玩家实体和物理。

要求：
- 玩家 AABB、眼睛高度、重力、跳跃、行走、奔跑、飞行。
- 与方块碰撞：使用轴分离扫掠 AABB，防止穿墙和卡入方块。
- 输入：WASD，空格跳跃，Shift 下蹲/奔跑，F 切换飞行。
- 相机跟随玩家，支持第一人称。
- 单元测试碰撞解析，覆盖地面、墙壁、天花板。

完成后运行游戏验证，提交 Git。
```

### 阶段 6：方块交互

```text
进入阶段 6：实现方块破坏与放置。

要求：
- 从相机发射射线，使用 DDA 体素遍历，最大距离 5。
- 高亮选中方块，显示线框。
- 左键破坏方块，右键放置方块。
- 不能把方块放在玩家 AABB 内。
- 修改方块后更新对应区块网格。
- 可选：添加简单音效占位。

完成后运行游戏验证，提交 Git。
```

### 阶段 7：UI 与物品栏

```text
进入阶段 7：实现基础 UI。

要求：
- 2D 渲染器，正交投影，支持纹理和颜色。
- 十字准星。
- 调试 HUD：FPS、坐标、区块坐标、朝向。
- 物品栏热键栏，1-9 选择方块。
- 简单方块选择 UI。
- 不使用 Minecraft 的材质或 UI 资源。

完成后运行游戏验证，提交 Git。
```

### 阶段 8：存档与数据驱动

```text
进入阶段 8：实现存档。

要求：
- 世界种子保存与加载。
- 区块数据序列化到 region 文件或 JSON/NBT 风格格式。
- 保存/加载玩家位置、物品栏、方块修改。
- 数据包：用 JSON 定义方块属性。
- 测试序列化往返，确保数据一致。

完成后运行游戏验证，提交 Git。
```

### 阶段 9：实体与生物

```text
进入阶段 9：添加基础实体系统。

要求：
- 使用组件式 Entity 或轻量 ECS，包含位置、速度、渲染组件。
- 简单生物：被动移动，AABB 物理。
- 实体与方块碰撞，与玩家碰撞。
- 实体渲染，使用简单立方体模型。
- 单元测试实体更新和碰撞。

完成后运行游戏验证，提交 Git。
```

### 阶段 10：优化与质量

```text
进入阶段 10：优化性能与代码质量。

要求：
- 视锥剔除。
- 纹理图集、批次渲染，减少 draw call。
- 多线程区块生成和网格构建。
- 帧率统计与性能分析。
- 目标：渲染距离 8，稳定 60 FPS。
- 补充文档和架构说明。

完成后运行测试和游戏验证，提交 Git。
```

### 阶段 11：打包与发布

```text
进入阶段 11：打包项目。

要求：
- 使用 Gradle shadowJar 或 jlink 生成可运行 jar。
- 生成 Windows/macOS/Linux 启动脚本。
- 设置版本号。
- 完善 README、许可证、致谢。
- 最终运行测试和游戏验证。

完成后提交 Git。
```

## 四、关键注意事项

1. **版权**：只模仿玩法和架构，不要复制 Minecraft 代码、材质、音效、名称、商标。项目名用 VoxelGame。
2. **MVP 优先**：先做“能走、能看、能放方块”的最小版本，再扩展。
3. **每步可运行**：每个阶段结束必须能 `./gradlew run` 和 `./gradlew test`。
4. **小步提交**：每完成一个垂直切片就 Git 提交。
5. **让 Claude Code 验证**：要求它运行命令、看日志、修到通过，而不是只生成代码。
6. **控制上下文**：用 `CLAUDE.md` 保存长期约束，新会话先读它。

```text
请先创建 CLAUDE.md，内容使用我提供的项目宪法。然后执行阶段 0：需求澄清与规划，不要写代码。
```
