
### MySQL 底层常用的存储引擎是什么？

**这个问题非常基础且关键，我直接回答：目前生产环境绝对主流是 InnoDB。**

从 MySQL 5.5.5 版本开始，**InnoDB** 就成为了默认的存储引擎。日常面试中，只要提到 MySQL 存储引擎，几乎默认指 InnoDB。

**InnoDB 区别于其他引擎（如 MyISAM）的四大核心优势（面试必背）：**

|对比维度|**InnoDB（主流）**|MyISAM（旧版）|面试阐述重点|
|---|---|---|---|
|**事务（ACID）**|**支持**，具有完善的 Redo Log（重做日志，保证持久性）和 Undo Log（回滚日志，保证原子性）|**不支持**|这是业务系统选 InnoDB 的根本原因|
|**锁粒度**|**行级锁（Row-level Lock）**，并发高|表级锁（Table-level Lock），并发差|InnoDB 行锁是基于索引实现的，执行不带索引的 SQL 会退化为表锁|
|**外键约束**|**支持**|不支持|虽然互联网项目大多禁用物理外键（应用层做逻辑外键），但 InnoDB 底层支持|
|**聚簇索引**|**是（Clustered Index）**，数据和主键索引存储在一起|非聚簇，数据和索引分开存储|InnoDB 通过主键直接找到数据行，二级索引需要回表|

**底层数据存储结构（Show Depth）：**  
InnoDB 的数据存储在磁盘的 `.ibd` 文件中，底层使用 **B+ 树（B+ Tree）** 数据结构。B+ 树的特点是**叶子节点存储数据页（默认 16KB），并且叶子节点间用双向链表连接**，非常适合进行磁盘 I/O 范围的顺序扫描。
