## 一、对象转 JSON 的方法怎么命名

**结论：用 `toJson()`，不要 `objToString` / `toString`。**

|   |   |
|---|---|
|命名|评价|
|`toJson()`|✅ 社区共识（Gson 的 `toJson(obj)` 先例），清爽|
|`toJsonString()`|⚠️ 能接受，但"类型写进名字"属于冗余（返回类型已说明是 String）|
|`objToJson()`|⚠️ `obj` 前缀冗余，方法本身就在对象上|
|`toString()` / `objToString()`|❌ 语义雷区|

**为什么不能 `toString`**：`toString` 有既定契约——给人看的、用于调试的字符串。重写成 JSON 会导致：

- JS 里 `` `${obj}` ``、`'x' + obj`、`console.log(obj)` 全部自动调用它 → 日志里一坨 JSON，还可能泄露敏感字段

- Java 里 `Object.toString` 是通用契约，改语义会误导排查问题的人

**各语言惯用写法**

|   |   |   |
|---|---|---|
|语言|惯用|备注|
|JS / TS|`toJSON()`|**标准**：`JSON.stringify` 会自动调用它（返回可序列化值，非字符串）|
|Java|`toJson()`|或用框架原生：`writeValueAsString` / `JSON.toJSONString`|
|Kotlin|`encodeToString()`|kotlinx.serialization|
|Go / Rust / C#|`json.Marshal` / `to_string` / `Serialize`|走标准库，不自己起名|
|Python|`to_dict()` + `json.dumps()`|拆两步：结构转换 ≠ 序列化|

**歧义提醒**：`toJson` 到底返回字符串还是普通对象/Map？两者都要时命名区分——`toJsonValue()` / `toJsonString()`。

## 二、`Class<T> clazz` 是什么

|   |   |
|---|---|
|部分|含义|
|`Class<T>`|反射类型：一个"描述某个类的对象"。`String.class` 就是它的一个值|
|`<T>`|泛型参数：这个 Class 对象代表的具体类型|
|`clazz`|变量名。`class` 是关键字不能用，社区习惯写 `clazz`（也有 `clz`/`type`/`targetClass`）|

**为什么必须传它：类型擦除。** 泛型只在编译期存在，运行时 `List<User>` 和 `List<String>` 都是 `List`。想"凭空造一个 T"，运行时不知道 T 是谁，只能由调用方把 Class 递进来。

**反序列化三兄弟（都靠这个参数）**

**怎么传**

**两个坑**

1. 嵌套泛型失效：`List<User>.class` 非法。要保留元素类型 → Jackson `TypeReference<List<User>>(){}`、Gson `TypeToken<List<User>>(){}.getType()`

2. `int.class != Integer.class`，JSON 里的 null 反序列化成 `int` 会炸

## 三、什么是 Class 对象

**一句话：JVM 为每个类生成的一张"档案卡"——它本身是对象，描述的是"这个类长什么样"。**

|   |   |
|---|---|
|概念|类比|
|类 `User`|图纸|
|实例 `new User()`|按图纸盖的房子|
|Class 对象|这栋楼的房产档案（户型、承重墙位置）|

**五个关键事实**

1. 每个类只有一个 Class 对象：`User.class == user.getClass()` 恒为 true

2. 它不是类本身，是 `java.lang.Class` 的实例；`User.class` 的类型是 `Class<User>`

3. JVM 加载 .class 字节码时创建它，存字段/方法/构造器/注解/父类/接口等元数据

4. 它是**反射的唯一入口**

5. 基本类型和数组也有：`int.class`、`String[].class`

**能干什么（反射 API）**

**为什么重要**：Spring 扫注解建 Bean、Jackson 反序列化、MyBatis 行映射、JUnit 找 @Test、Tomcat 加载 Servlet——全靠它。

**三个坑**

- 泛型信息没了（`List<String>.class` 不存在）

- 数组名字怪：`String[].class.getName()` = `[Ljava.lang.String;`

- 反射有代价：绕过编译检查、慢、`setAccessible` 破坏封装（JDK 9+ 模块化可能被拒）

## 五、代码 Review：`jsonToObj` 的 4 个改进点

1. **`(T) str` → `clazz.cast(str)`**：前者是未检查强转，擦除后运行时不校验，错误延迟到调用处才炸

2. **`Prase` → `Parse`**，日志带上截断的原文，方便定位是哪条数据

3. **返回 null 有两种含义**（空输入 / 解析失败），调用方分不清

4. **`isEmpty` → `isBlank`**：全空格也是无效 JSON
