# Jackson 核心配置详解

> 场景：一个全局 `ObjectMapper` 兜底整个项目。
> 目标：**反序列化容错、序列化不失败、日期格式统一、支持 Java 8 时间类型、少写注解。**
> 版本基线：Jackson 2.10+（代码用 `JsonMapper.builder()`，2.13+ 更推荐；注解常量以 2.15~2.17 为准）。

---

## 0. 全景表：每个开关到底管哪一段

| # | 配置 | 所属枚举 | **默认值** | 作用阶段 | 一句话 |
|---|---|---|---|---|---|
| 1 | `FAIL_ON_UNKNOWN_PROPERTIES=false` | `DeserializationFeature` | `true` | 反序列化 | JSON 里多出字段不报错 |
| 2 | `FAIL_ON_INVALID_SUBTYPE=false` | `DeserializationFeature` | `true` | 反序列化（多态） | 类型标识不认识就返回 `null` |
| 3 | `WRITE_DATES_AS_TIMESTAMPS=false` | `SerializationFeature` | `true` | 序列化 | 日期写成字符串而不是数字/数组 |
| 4 | `FAIL_ON_EMPTY_BEANS=false` | `SerializationFeature` | `true` | 序列化 | 空对象写成 `{}` 而不是抛异常 |
| 5 | `WRITE_DATE_KEYS_AS_TIMESTAMPS=false` | `SerializationFeature` | `false`（2.16+） | 序列化（Map 的 key） | 日期作为 key 时也写字符串 |
| 6 | `serializationInclusion(NON_NULL)` | `JsonInclude.Include` | `ALWAYS` | 序列化 | `null` 字段直接不输出 |
| 7 | `USE_ANNOTATIONS=false` | `MapperFeature` | `true` | 全局 | 完全不认 Jackson 注解 |
| 8 | `addModule(new JavaTimeModule())` | `Module` | 未注册 | 双向 | 让 `LocalDateTime` 等能被处理 |
| 9 | `defaultDateFormat(...)` | — | ISO / **UTC** | 双向 | 只管 `java.util.Date` |
| 10 | `SimpleModule` 自定义 | `Module` | — | 双向 | 管 `LocalDateTime` 的格式 |

**记住这条主线**：1、2 是"读的时候别炸"，3、4、5、6 是"写的时候别炸也别难看"，7 是"别依赖注解"，8、9、10 是"时间类型特殊照顾"。

## 1. 反序列化容错

### 1.1 `FAIL_ON_UNKNOWN_PROPERTIES = false`

**默认 `true` 时会发生什么**

上游发来 `{"name":"张三","age":18,"vip":true}`，你的 `User` 只有 `name`、`age` 两个字段 → 直接抛：

```
com.fasterxml.jackson.databind.exc.UnrecognizedPropertyException:
Unrecognized field "vip" (class com.demo.User), not marked as ignorable
```

**设为 `false`**：多余字段被静默丢弃，正常返回 `User`。

**为什么需要它**：上游加字段是常态，你不该为对方的扩容而改代码。这是"消费方防御"。

**代价（必须知道）**

1. **拼写错误被吞掉**：`{"nmae":"张三"}` → `name` 为 `null`，全程不报错，等到业务层才 `NPE`，排查时离现场已经很远。
2. **契约漂移无人发现**：对方把 `userName` 改成了 `username`，你的系统静默收到 `null`，可能一整批数据都是错的。
3. **安全审计失明**：如果 JSON 里混进了不该有的敏感字段，你也不知道。

**三种收敛手段（按推荐度）**

```java
// ① 只对需要宽容的类放开，而不是全局
@JsonIgnoreProperties(ignoreUnknown = true)
public class ExternalOrderDTO { ... }

// ② 把多余字段收集起来，至少能打日志
@JsonAnySetter
private Map<String, Object> extras = new HashMap<>();

// ③ 测试/预发环境保持 true，生产才 false（最稳）
boolean strict = !"prod".equals(env);
mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, strict);
```

> 实践建议：**全局 `false` + 单测里用一个严格 mapper 做契约校验**。生产要宽容，测试要挑剔。

---

### 1.2 `FAIL_ON_INVALID_SUBTYPE = false`

**只在多态反序列化时有用**，也就是字段上有 `@JsonTypeInfo` 的情况：

```java
@JsonTypeInfo(use = JsonTypeInfo.Id.NAME, property = "type")
@JsonSubTypes({
    @JsonSubTypes.Type(value = AlipayPay.class, name = "alipay"),
    @JsonSubTypes.Type(value = WxPay.class,    name = "wx")
})
public abstract class PayChannel { }

public class Order { public PayChannel channel; }
```

- **默认 `true`**：JSON 里出现 `{"type":"unionpay"}`（当前版本还没支持的子类型）→ 抛 `InvalidTypeIdException`
- **设为 `false`**：不抛异常，**字段返回 `null`**

**为什么设 `false`**：老客户端/新上游可能发来你这一版还没实现的渠道，宁可这条数据缺一块，也别让整条报文解析失败（尤其批量消费场景，一条脏数据卡死整个队列）。

**代价**

1. **`null` 比异常更难查**：异常有栈、有上下文；`null` 会在三层之后变成 `NPE`，或者更糟——被 `if (channel != null)` 静默跳过，业务少算了钱。
2  **安全红线**：多态反序列化历来是 Java 反序列化漏洞的重灾区。**千万不要**为了"容错"去开：

```java
// ☠️ 绝对不要
mapper.activateDefaultTyping(LaissezFaireSubTypeValidator.instance,
        ObjectMapper.DefaultTyping.NON_FINAL);
```

它允许 JSON 里写任意类名，等于把"能 new 什么类"的控制权交给了外部输入。

**正确姿势**：`use = Id.NAME` + 显式 `@JsonSubTypes` 白名单（如上），或 `Id.CUSTOM` 自己映射表。既然用了白名单，`FAIL_ON_INVALID_SUBTYPE=false` 就只是"白名单外的 id 给 null"，风险可控。

**同类容错项**（按需补）

| 配置 | 作用 |
|---|---|
| `READ_UNKNOWN_ENUM_VALUES_AS_NULL` | 未知枚举值变 `null`（默认抛异常），配 `@JsonEnumDefaultValue` 更优雅 |
| `ACCEPT_SINGLE_VALUE_AS_ARRAY` | 单个值兼容成单元素数组（上游时而传 `1` 时而 `[1]`） |
| `ACCEPT_EMPTY_STRING_AS_NULL_OBJECT` | `""` 当 `null`（老系统大量传空串） |
| `FAIL_ON_NULL_FOR_PRIMITIVES` | 默认 `false`：`int` 字段收到 `null` 会变 `0`；想严格就置 `true` |

## 2. 序列化容错

### 2.1 `WRITE_DATES_AS_TIMESTAMPS = false`

**默认 `true`** 时，日期被写成"机器友好、人类懵逼"的形状：

| 类型 | 默认（`true`） | 设为 `false` |
|---|---|---|
| `java.util.Date` | `1730084727000` | `"2026-10-28T11:05:27.000+00:00"` |
| `LocalDateTime`（已注册 JavaTimeModule） | `[2026,10,28,11,5,27]` | `"2026-10-28T11:05:27"` |
| `LocalDate` | `[2026,10,28]` | `"2026-10-28"` |

**为什么必须关**：

1. 数组形式 `[2026,10,28,...]` 前端几乎没法直接用，还得自己拼
2. 时间戳丢掉"是哪个时区/是不是本地时间"的语义，跨时区必错
3. 接口文档、日志、抓包全都不好读

**⚠️ 关键认知**：设成 `false` 只是变成 **ISO-8601**（带 `T`），**不是** `yyyy-MM-dd HH:mm:ss`。想要后者，必须走 4.3 的自定义 `SimpleModule`——这正是为什么配置里 3 和 10 要同时存在。

---

### 2.2 `FAIL_ON_EMPTY_BEANS = false`

**默认 `true`**：如果一个类"找不到任何可序列化的属性"，抛：

```
InvalidDefinitionException: No serializer found for class com.demo.Foo
and no properties discovered to create BeanSerializer
```

**什么时候会触发（都是真实踩过的）**

| 场景 | 原因 |
|---|---|
| 空类 / 只有 `private` 字段没 getter | Jackson 默认按 getter 找属性 |
| Lombok 忘了加 `@Data`/`@Getter`，或注解处理器没生效 | 同上，编译后真的没 getter |
| getter 被 `@JsonIgnore` 掉了 | 唯一属性被屏蔽 |
| 返回了 Hibernate 懒加载代理 / CGLIB 代理 / `Optional` 之类 | 代理类本身没属性 |
| 返回 `java.io.File`、`InputStream` 等 | 无属性可写 |
| 混用了 `USE_ANNOTATIONS=false` | 类上的 `@JsonAutoDetect` 一起失效 |

**为什么设 `false`**：这些对象往往是"顺带出现在响应里"的（比如 `Result<Foo>` 的某个附属字段），不该因为一个边角对象让整个接口 500。

**代价**

1. 输出 `"foo": {}`，前端拿到空对象还以为是"有数据但字段为空"，比 `null` 更误导
2. **掩盖了"缺 getter"这个真 bug**——很多人就是靠这个开关让编译期该发现的问题拖到了线上

> 折中：生产 `false`，同时用 ArchUnit / 单测扫一遍"所有对外 DTO 都有可序列化属性"，别让开关变成遮羞布。

---

### 2.3 `WRITE_DATE_KEYS_AS_TIMESTAMPS = false`

**只管一件事**：`Map<Date, V>` / `Map<LocalDate, V>` 这种**日期作 key** 的情况。

```java
Map<Date, Integer> m = new HashMap<>();
// 默认（该特性未开）：{"2026-10-28":"..."} 这种 key 走格式化字符串
// 若开了 timestamps：{"1730084727000": 1}
```

**版本注意**：这个特性 **Jackson 2.16 才引入**（默认就是 `false`）。
- 2.16+：写这行是"显式声明意图"，属于防御性配置
- 2.16 以下：**枚举常量不存在，代码直接编译不过** —— 升级 Jackson 或删掉这行

它和 2.1 是两套开关：2.1 管 **value**，2.3 管 **key**。老版本里日期 key 固定走 `StdDateFormat` 字符串，不需要额外配置。

---

### 2.4 `serializationInclusion(NON_NULL)`

**默认 `ALWAYS`**：所有字段都输出，`null` 也输出 `"name": null`。

**设为 `NON_NULL`** 后，值为 `null` 的属性**整个 key 都不出现**。

```json
// ALWAYS
{"id":1,"name":"张三","phone":null,"tags":null}
// NON_NULL
{"id":1,"name":"张三"}
```

**为什么用**：省带宽（大列表尤其明显）、避免前端把 `null` 当"字段存在"处理、减少无意义的字段噪音。

**三个必须知道的局限**

1. **只管 Bean 属性，不管容器内部**

```java
Map<String, Object> m = new HashMap<>();
m.put("a", null);                       // NON_NULL 照样输出 {"a":null}
List<String> l = Arrays.asList("x", null); // 照样是 ["x", null]
```

要连内容一起过滤：

```java
mapper.setDefaultPropertyInclusion(
    JsonInclude.Value.construct(JsonInclude.Include.NON_NULL,   // 属性值
                               JsonInclude.Include.NON_NULL));  // 容器内容
```

2. **`NON_NULL` ≠ `NON_EMPTY`**

| 值 | `NON_NULL` | `NON_EMPTY` | `NON_ABSENT` |
|---|---|---|---|
| `null` | 去掉 | 去掉 | 去掉 |
| `""` / `[]` / `{}` | **保留** | 去掉 | 去掉 |
| `Optional.empty()` | 保留（`{}`） | 保留 | 去掉 |

3. **API 兼容性风险**：字段"消失"和"值为 null"对某些前端/强类型客户端是两种语义。`Optional<T>` 的客户端可能反序列化失败。**改这个开关属于契约变更**，老接口慎动。

> 另：`ObjectMapper.setSerializationInclusion()` 在 2.9 起已 deprecated，新代码用 `setDefaultPropertyInclusion()` 或 builder 的 `serializationInclusion()`。

## 3. 注解控制

### 3.1 `USE_ANNOTATIONS = false`

**这是整套配置里最激进、也最危险的一刀。**

**它关掉的不是"一点点注解"，而是所有 Jackson 注解**：

| 注解 | 关掉后的后果 |
|---|---|
| `@JsonProperty("user_name")` | 重命名失效 → 字段名对不上，数据全空 |
| `@JsonIgnore` | **失效 → 敏感字段（password、idCard）直接出现在响应里** |
| `@JsonFormat(pattern=...)` | 日期格式回到默认，接口格式突变 |
| `@JsonSerialize` / `@JsonDeserialize` | 自定义序列化器全部失效 |
| `@JsonCreator` / `@JsonValue` | 反序列化构造器、枚举自定义值失效 |
| `@JsonTypeInfo` / `@JsonSubTypes` | 多态反序列化整体失效 |
| `@JsonIgnoreProperties` | 类级容错配置失效 |
| `@JsonAutoDetect` | 属性发现规则回到默认 |

**为什么有人这么配**：想要"POJO 保持纯净、格式统一由全局管"，避免每个类上挂一堆 `@JsonFormat`、`@JsonProperty`，DTO 里不出现 Jackson 依赖。

**应当同时具备的条件（缺一不可）**

```java
// 重命名靠全局命名策略（蛇形/驼峰自动转换）
mapper.setPropertyNamingStrategy(PropertyNamingStrategies.SNAKE_CASE);

// 个别字段特殊处理靠 Mixin，而不是注解
abstract class UserMixin {
    @JsonIgnore abstract String getPassword();   // Mixin 里的注解同样依赖 USE_ANNOTATIONS
}
mapper.addMixIn(User.class, UserMixin.class);
```

**注意**：`MapperFeature` 在 2.13 之后已被标记废弃，官方推荐用 builder：

```java
JsonMapper.builder().disable(MapperFeature.USE_ANNOTATIONS).build();
```

**我的建议（直言）**

> 除非你从项目第一天就定死这条规矩、且团队全部遵守，否则**不要关**。
> 它最大的风险不是"格式不对"，而是 **`@JsonIgnore` 静默失效导致敏感字段泄露**——这种事故不会报错，只会在某天被人截图发到群里。
> 如果只是想"少写注解"，用全局命名策略 + `@JsonInclude` 默认值 + Mixin 就够，不必动这个总闸。

## 4. 日期时间配置（最容易翻车的一段）

### 4.1 `addModule(new JavaTimeModule())`

**依赖**

```xml
<dependency>
    <groupId>com.fasterxml.jackson.datatype</groupId>
    <artifactId>jackson-datatype-jsr310</artifactId>
</dependency>
```

**不注册会怎样**

- Jackson 2.12+：直接抛
  `InvalidDefinitionException: Java 8 date/time type java.time.LocalDateTime not supported by default: add Module "com.fasterxml.jackson.datatype:jackson-datatype-jsr310"`
- 更早的版本：把 `LocalDateTime` 当成普通 Bean，输出一坨 `{"year":2026,"month":"OCTOBER","dayOfMonth":28,...}`

**注册后**：`LocalDateTime` 支持双向转换，输出形态受 `WRITE_DATES_AS_TIMESTAMPS` 控制（见 2.1）。

**Spring Boot 用户**：只要类路径上有 `jackson-datatype-jsr310`，Boot 会自动注册，无需手写——但你**自己 `new ObjectMapper()` 的那个工具类不会**（见第 6 节坑 6）。

也可以用 `mapper.findAndRegisterModules()` 自动扫描所有模块，缺点是依赖运行时类路径、启动略慢、行为不可见，生产更推荐显式注册。

---

### 4.2 `defaultDateFormat(new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"))`

**它只管 `java.util.Date` / `Calendar`。**

⚠️ **最常见的误解：以为设了它，`LocalDateTime` 就变成 `yyyy-MM-dd HH:mm:ss` 了——并不会。**
`defaultDateFormat` 走的是 `DateFormat` 体系，而 `java.time.*` 由 `JavaTimeModule` 独立处理，两者完全不搭界。所以才有 4.3。

**⚠️ 更隐蔽的坑：时区**

Jackson 的 `ObjectMapper` 默认时区是 **UTC**。不设时区直接 `defaultDateFormat`，在北京服务器上会输出：

```
数据库里：2026-10-28 11:05:27（本地时间）
接口输出：2026-10-28 03:05:27   ← 少了 8 小时
```

因为它把 `Date`（时间点）按 UTC 解释再格式化。**必须显式设时区**：

```java
mapper.setTimeZone(TimeZone.getTimeZone("Asia/Shanghai"));
// 或者在 formatter 里带上，二选一，别只改一处
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
sdf.setTimeZone(TimeZone.getTimeZone("Asia/Shanghai"));
```

**线程安全**：`SimpleDateFormat` 本身不安全，但 Jackson 取用时会 `clone()`（`SerializerProvider#getDateFormat` 返回克隆），所以传给 `ObjectMapper` 是安全的；**自己代码里共用同一个实例去 `format()` 才不安全**。

> 顺带：`Date` 这个类型本身就丢精度、带时区歧义，新项目该全用 `java.time`，`defaultDateFormat` 只是给历史字段兜底。

---

### 4.3 `SimpleModule` 自定义 `LocalDateTime`

**为什么必须自己写**：`defaultDateFormat` 管不到 `java.time`，而 `JavaTimeModule` 默认输出 ISO-8601（`2026-10-28T11:05:27`，带 `T`）。国内业务接口几乎都要求 `yyyy-MM-dd HH:mm:ss`。

**完整代码（可直接抄）**

```java
public final class JacksonTimeSupport {

    private static final DateTimeFormatter DTF =
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

    private JacksonTimeSupport() {}

    public static Module localDateTimeModule() {
        SimpleModule module = new SimpleModule("custom-local-datetime");

        // 序列化：LocalDateTime -> "yyyy-MM-dd HH:mm:ss"
        module.addSerializer(LocalDateTime.class, new JsonSerializer<LocalDateTime>() {
            @Override
            public void serialize(LocalDateTime value, JsonGenerator gen,
                                  SerializerProvider provider) throws IOException {
                gen.writeString(DTF.format(value));
            }
        });

        // 反序列化："yyyy-MM-dd HH:mm:ss" -> LocalDateTime
        module.addDeserializer(LocalDateTime.class, new JsonDeserializer<LocalDateTime>() {
            @Override
            public LocalDateTime deserialize(JsonParser p, DeserializationContext ctxt)
                    throws IOException {
                String text = p.getValueAsString();
                if (text == null || text.isBlank()) {
                    return null;                     // 空串/null 都当 null，别让 "" 抛异常
                }
                return LocalDateTime.parse(text.trim(), DTF);
            }
        });

        return module;
    }
}
```

**三个细节，漏一个就出问题**

1. **注册顺序：自定义模块必须在 `JavaTimeModule` 之后 `addModule`**
   Jackson 的模块是"后注册优先级更高"（新序列化器插到列表头部）。顺序反了，你的格式会被 `JavaTimeModule` 的 ISO 序列化器覆盖，看起来"配置没生效"。

```java
mapper.addModule(new JavaTimeModule());          // 先：基础能力
mapper.addModule(JacksonTimeSupport.localDateTimeModule()); // 后：覆盖格式
```

2. **用 `DateTimeFormatter` 而不是 `SimpleDateFormat`**
   `DateTimeFormatter` 不可变、线程安全；`SimpleDateFormat` 不是。

3. **反序列化必须自己处理 `null` / 空串 / 空格**
   默认实现遇到 `""` 会抛 `DateTimeParseException`。上游传空串是常态。

**另一半没管的类型**

上面只覆盖了 `LocalDateTime`。若项目还有 `LocalDate`、`LocalTime`、`OffsetDateTime`，需要各自 `addSerializer`/`addDeserializer`（或给它们也配上 formatter），否则它们仍是 ISO 格式。`LocalDate` 一般 ISO 的 `2026-10-28` 就够用，可以不管。

## 5. 完整配置代码

### 5.1 原生 Jackson（工具类 / 非 Spring 环境）

```java
ObjectMapper mapper = JsonMapper.builder()
        // ① 反序列化容错
        .disable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES)
        .disable(DeserializationFeature.FAIL_ON_INVALID_SUBTYPE)
        // ② 序列化容错
        .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)
        .disable(SerializationFeature.FAIL_ON_EMPTY_BEANS)
        .disable(SerializationFeature.WRITE_DATE_KEYS_AS_TIMESTAMPS)  // 需 2.16+
        .serializationInclusion(JsonInclude.Include.NON_NULL)
        // ③ 注解策略（谨慎！确认无 @JsonIgnore 保护敏感字段）
        // .disable(MapperFeature.USE_ANNOTATIONS)
        // ④ 时间
        .defaultTimeZone(TimeZone.getTimeZone("Asia/Shanghai"))
        .defaultDateFormat(new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"))
        .addModule(new JavaTimeModule())
        .addModule(JacksonTimeSupport.localDateTimeModule())
        .build();
```

### 5.2 Spring Boot（推荐用 Customizer，别自己 new）

```java
@Configuration
public class JacksonConfig {

    @Bean
    public Jackson2ObjectMapperBuilderCustomizer jacksonCustomizer() {
        return builder -> builder
                .featuresToDisable(
                        DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES,
                        DeserializationFeature.FAIL_ON_INVALID_SUBTYPE,
                        SerializationFeature.WRITE_DATES_AS_TIMESTAMPS,
                        SerializationFeature.FAIL_ON_EMPTY_BEANS,
                        SerializationFeature.WRITE_DATE_KEYS_AS_TIMESTAMPS)
                .serializationInclusion(JsonInclude.Include.NON_NULL)
                .timeZone(TimeZone.getTimeZone("Asia/Shanghai"))
                .dateFormat(new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"))
                .modulesToInstall(new JavaTimeModule(),
                                  JacksonTimeSupport.localDateTimeModule());
    }
}
```

用 `modulesToInstall`（追加）而不是 `modules`（覆盖），否则 Boot 自动装的其它模块会被顶掉。

## 6. 坑清单（按踩中概率排序）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | 以为 `defaultDateFormat` 能管 `LocalDateTime` | `2026-10-28T11:05:27`，`T` 去不掉 | 加 4.3 的 `SimpleModule` |
| 2 | 没设时区 | 时间少 8 小时 | `setTimeZone(Asia/Shanghai)` |
| 3 | 模块注册顺序反了 | 自定义格式"没生效" | 自定义模块放 `JavaTimeModule` 之后 |
| 4 | `USE_ANNOTATIONS=false` 但项目里有 `@JsonIgnore` | 密码/身份证出现在响应里 | 别关；或改 Mixin + 全局过滤器 |
| 5 | 以为 `NON_NULL` 会清掉 Map 里的 null | `{"a":null}` 还在 | `setDefaultPropertyInclusion` 带 content |
| 6 | 工具类 `new ObjectMapper()` 单独一份 | Spring 接口格式对、工具类格式不对 | 统一由 `JacksonUtils.getMapper()` 或注入 Spring 的 mapper |
| 7 | `FAIL_ON_EMPTY_BEANS=false` 掩盖缺 getter | 响应里一堆 `{}` | 单测扫 DTO；Lombok 检查注解处理 |
| 8 | `FAIL_ON_INVALID_SUBTYPE=false` | 字段莫名 `null` → 三层后 NPE | 日志记录 subtype 未命中 |
| 9 | 老版本引用 `WRITE_DATE_KEYS_AS_TIMESTAMPS` | 编译不过 | 升到 2.16+ 或删掉 |
| 10 | 全局 `FAIL_ON_UNKNOWN_PROPERTIES=false` 后无契约校验 | 上游改名，静默全空 | 单测用严格 mapper 做 schema 校验 |

## 8. 一句话总结

**这套配置的本质是"用全局开关换掉逐类的注解"**——宽进（读的时候容错）、严出（写的时候不出错）、时间统一、少挂注解。
但宽容是有代价的：**每一个 `FAIL_ON_*=false` 都在把"报错"换成"静默"**，所以生产宽松、测试严格，才是这套配置的正确用法。
