
## final、finally、finalize 的区别

### 1. final（关键字，用于“不可变”）

| 修饰对象 | 作用 | 举例 |
|---------|------|------|
| **变量** | 值不可改（基本类型）或引用不可改（引用类型，但对象内容可变） | `final int a = 1;` 后不能再赋值 |
| **方法** | 方法不可被子类重写（Override） | 保护核心逻辑不被篡改 |
| **类** | 类不可被继承 | `final class String` 保证安全不可变 |

---

### 2. finally（异常处理关键字，用于“兜底”）

- `try-catch-finally` 中的一环。
- **finally 块中的代码一定会执行**（即使 try 中有 return 或异常被抛出）。
- 用途：释放资源，如关闭 IO 流、数据库连接等。
- **唯一不执行的情况**：JVM 在 try 块中直接 `System.exit(0)` 或系统崩溃。

```java
try {
    // 可能异常的代码
    return 1;
} catch (Exception e) {
    // 处理异常
} finally {
    // 无论如何都会执行，常用于关流、放锁
}
```

---

### 3. finalize（Object 类的一个方法，已过时）

- 是 `Object` 类的一个 `protected` 方法。
- 在对象被垃圾回收前，GC 会调用一次（最多一次）。
- 设计初衷：给对象一个“临终交代”的机会，比如释放外部资源。
- **但实际生产中基本不用**：
  - 调用时机不确定，可能很久甚至都不执行。
  - 性能损耗大。
  - JDK 9 起已被标记为 `@Deprecated`，JDK 18+ 已明确移除计划。
- 替代方案：显式资源管理，用 `try-with-resources` 或手动 `close()`。

---

### 一句话总结区别
- **final**：不可变（修饰类/方法/变量）
- **finally**：必须执行的兜底（异常处理用）
- **finalize**：不靠谱的遗言（已淘汰，别用）
