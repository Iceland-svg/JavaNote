Redis 哨兵（Sentinel）是一个基于分布式的组件，它通过监控（心跳），监控redis节点，触发领导者选举，自动执行故障转移（将从节点提升为主节点并重写配置），提供了高可用方案

哨兵节点是独立的redis-server进程，一般是以多个哨兵节点集合的形式存在的

自动化恢复过程

三个哨兵进程通过tcp长连接监控，定期发送心跳包，这样就能及时发现，主/从节点是否挂了，同时，需要多个哨兵进程共同“认同”，如果挂了，就会“推举”一个小领导来从现有从节点中挑一升为主节点，哨兵节点控制选中节点执行 slave of no one，并控制其他从节点slave of到新的主节点上，最后哨兵自动通知redis客户端程序，谁是新的主节点，写操作就会就在新的主节点上进行

编写配置文件

```
version: '3.7'
services:
  sentinel1:
    image: 'redis:5.0.9'
    container_name: redis-sentinel-1
    restart: always
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel1.conf:/etc/redis/sentinel.conf
    ports:
      - 26379:26379
  sentinel2:
    image: 'redis:5.0.9'
    container_name: redis-sentinel-2
    restart: always
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel2.conf:/etc/redis/sentinel.conf
    ports:
      - 26380:26379
  sentinel3:
    image: 'redis:5.0.9'
    container_name: redis-sentinel-3
    restart: always
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel3.conf:/etc/redis/sentinel.conf
    ports:
      - 26381:26379
networks:
  default:
    external:
      name: redis-data_default
```

doker通过端口映射可以让容器外访问容器内

```
bind 0.0.0.0
port 26379
sentinel monitor redis-master redis-master 6379 2
sentinel down-after-milliseconds redis-master 1000
```
