## 1 为什么要用线程池

由于频繁创建销毁开销很大，所以提前把线程创建好放到池子里面
目的是提高效率


---

## 2 线程池的核心参数
### （1） int corepoolSize 

核心线程数

### 核心线程：

一创建就申请的线程
### 临时线程：

核心线程处理不过来了就申请一些其他线程来帮忙，帮忙的就是临时线程
不忙的时候就释放临时线程，但是核心线程永远不会销毁，除非销毁整个线程池

### （2） int maximumPoolSize

最大线程数

### （3） long KeepAliveTime

线程的存活时间

### （4） TimeUnit unit

线程允许休息的最大时间

### （5） BlockingQueue workQueue

#### 任务队列

里面放的都是线程要执行的任务，每个任务都是Runnable来描述的，使用线程池的时候，先会创建线程，然后需要调用者放一些任务，线程就会从任务队列里取出任务来执行

### （6） ThreadFactory threadFactory

#### 线程工厂类
统一管理线程创建
工厂模式的设计初衷是为了弥补构造方法的缺陷，因为在构造方法中，为满足不同构造需求可能会出现需要重载的情况，重载要求我们方法名字相同，参数列表不同，但是实际上就是可能会出现参数列表也相同的构造方法，所以我们不用构造方法，让这个类不包含构造方法，单独写一个工厂类，在内部写静态方法，这样可以实现不同名字不同参数列表的构造
 
代码案例

### （7） RejectedExecutionHandler handler

#### 拒绝策略
如果任务队列满了，我们又再次添加新任务，这时候按道理是会阻塞的，但是在实际情景中，对于某个程序，如果需要高时效性，这里绝对不能阻塞

### 四种拒绝策略

（1） AbortPolicy
直接终止
（2） CallerRunsPolicy
让调用者来执行任务，调用者也是一个线程
（3） DiscardOldestPolicy
丢弃掉最老的任务
（4） DiscardPolicy
丢弃掉最新的任务

## 3 ExecutorService使用

本质上也是工厂类，创建不同风格的线程池

```java
public class useOfExcutorService {  
    public static void main(String[] args){  
        //固定线程数目的线程池，核心线程数和最大线程数都是4  
        ExecutorService service1 = Executors.newFixedThreadPool(4);  
        //核心线程数为0，最大线程数为“int最大值"的线程池  
        ExecutorService service2 = Executors.newCachedThreadPool();  
        //固定 只有一个线程的线程池  
        ExecutorService service3 = Executors.newSingleThreadExecutor();  
        //本质上是计时器，在一定时间之后执行放到这个线程中的任务  
        ExecutorService service4 = Executors.newScheduledThreadPool(10);  
  
        for (int i = 0; i < 100; i++) {  
            //由于匿名内部类的变量捕获,局部变量必须是final或者effective final  
            //final修饰的实例变量必须在构造时就初始化  
            //final修饰的变量必须初始化，而且不能二次赋(修改)  
            //final修饰的类不能被继承  
            //final修饰的方法不能重写  
            //final修饰引用类型引用不能变  
            //以下技巧可帮助避免变量捕获  
            int id = i;  
            service1.submit(new Runnable() {  
                @Override  
                public void run() {  
                    //此处是任务  
                    System.out.println("执行一些任务"+id);  
                }  
            });  
        }  
    }  
}
```

## 4 自实现线程池

```java
public class MyFixedThreadPool {  
    private BlockingQueue<Runnable> queue = new LinkedBlockingQueue<Runnable>();  
    //由于是固定线程数的，这里给线程数参数n，  
    public MyFixedThreadPool(int n){  
        //刚开始初始化时，没有任何任务，所有线程全部阻塞，其实也就是先把线程都创建好了  
        for (int i = 0; i < n; i++){  
            //不断的获取任务去执行  
            Thread thread = new Thread(()->{  
                try {  
                    while (true){  
                        //Runnable类对象其实就是任务  
                        //由于这里的任务是封装好的，不是直接裸露出来的代码  
                        //我们需要调用run()来执行任务  
                        //同时这里也避免了为每个任务创建线程，实现线程复用  
                        Runnable task = queue.take();  
                        //没有任务就阻塞这个线程，等到其他线程submit  
                        //要记住阻塞只会在一个线程里，i仍会继续++  
                        task.run();  
                    }  
                } catch (InterruptedException e) {  
                    e.printStackTrace();  
                }  
            });  
            thread.start();  
        }  
    }  
    //submit在使用的时候其实就是利用匿名内部类在参数括号里写任务  
    public void submit(Runnable task) throws InterruptedException{  
        //放任务到任务队列  
        queue.put(task);  
    }  
}
```

测试代码

```java
public class useOfMyFixedThread {  
    public static void main(String[] args) throws InterruptedException {  
        //创建线程池  
        MyFixedThreadPool myFixedThreadPool = new MyFixedThreadPool(3);  
  
        //给线程池任务去执行的代码  
        for (int i = 0; i < 100; i++){  
            int id = i;  
            myFixedThreadPool.submit(()->{  
                System.out.println("执行任务"+id);  
            });  
        }  
    }  
}
```
