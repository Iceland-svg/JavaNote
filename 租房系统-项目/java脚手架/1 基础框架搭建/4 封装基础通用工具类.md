泛型擦除问题

```
泛型擦除是什么？

Java中的泛型擦除（Type Erasure）是指Java编译器在编译泛型代码时，会移除泛型类型参数的相关
信息，使得⽣成的字节码中不包含泛型类型信息。这使得Java泛型在运⾏时（Runtime）表现为原始
类型（Raw Type）

泛型擦除为什么出现？

向后兼容：Java泛型是在Java 5中引⼊的，为了让新版本的代码与旧版本的Java代码兼容，泛型擦
除是⼀种简单有效的实现⽅式。因为泛型信息在编译时已经被擦除了，所以旧版本的JVM可以运⾏
包含泛型的新代码

类型安全：尽管泛型信息在编译时被擦除，但Java编译器在编译时会进⾏类型检查，确保泛型的使
⽤是安全的。这意味着你可以在编译时发现类型错误，⽽不是在运⾏时。

避免性能开销：如果JVM需要在运⾏时维护泛型类型信息，那么这将会引⼊额外的性能开销。泛型
擦除避免了这种开销，因为所有的类型信息在编译时就已经确定了

泛型擦除解决办法

对于常⻅的Collection如 List、Map 中包含泛型，需要先反序列化Collection类型为泛型的Collection
Type。
如果是ArrayList<YourBean>那么使⽤ObjectMapper 的
getTypeFactory().constructParametricType(collectionClass, YourBean.class); 如果是
HashMap<String,YourBean>那么 ObjectMapper 的
getTypeFactory().constructMapType(HashMap.class,String.class, YourBean.class);
```

### Jackson核心配置
### Jackson核心配置详解：

1. `configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false)`
在反序列化时，当遇到 JSON 数据中存在 Java 对象对应类中没有定义的属性时，默认情况下 Jackson 会抛出异常。通过将此配置项设置为 false，允许在反序列化时忽略这些未知的属性，不会因为出现额外的属性而导致反序列化失败，增强了对不同来源 JSON 数据的兼容性。

2. `configure(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS, false)`
在序列化时，如果 Java 对象中包含日期类型默认情况下 Jackson 可能会将日期转换为一个时间戳（即从某个特定时间点开始到当前时间经过的毫秒数等形式的数值）来表示。将此配置设置为 false，意味着不采用时间戳的方式表示日期，而是会按照后续配置的其他日期相关格式进行序列化，以便生成更具可读性的日期格式表示在 JSON 数据中。

3. `configure(SerializationFeature.FAIL_ON_EMPTY_BEANS, false)`
在序列化时，Java 对象中没有任何属性值（为空），默认情况下 Jackson 可能会抛出异常。设置此后，允许将这样的对象进行序列化，即便对象没有实质内容也能生成对应的 JSON 表示（通常可能是一个空的 JSON 对象 {}），避免了因为空对象导致序列化失败的情况。

4. `configure(DeserializationFeature.FAIL_ON_INVALID_SUBTYPE, false)`
在反序列化时，如果 JSON 数据中指定的类型信息与预期的 Java 类型层次结构不匹配（例如类型标识错误的情况），默认会抛出异常。将这一配置设置为 false，可以放宽这种限制，使得在遇到类型不太准确但仍有可能处理的情况下，尝试继续进行反序列化而不是直接失败，提高了对可能存在错误类型的 JSON 数据的容错性。

5. `configure(SerializationFeature.WRITE_DATE_KEYS_AS_TIMESTAMPS, false)`
在序列化时，如果 Java 对象中以日期类型作为键（比如在 Map 中，键是 Date 类型等元素的情况）的结构，如果设置为 true 会将日期键转换为时间戳形式。设置为 false 则按照其他日期相关配置来处理，保证日期键也以期望的格式进行序列化，使得整个 JSON 结构中日期相关内容都能保持统一的格式呈现。（默认值为 false）

6. `configure(MapperFeature.USE_ANNOTATIONS, false)`
Jackson 支持通过在 Java 类的属性或方法上添加各种注解来定制序列化和反序列化行为。将此配置设置为 false，表示不依赖这些注解来进行相关操作，而是更多地依靠全局配置（如上述其他配置项）来掌控序列化和反序列化过程。适用于希望统一管理 JSON 处理规则，减少因注解使用不当或过多导致的复杂性的场景。

7. `addModule(new JavaTimeModule())`
这是序列化 LocalDateTime 和 LocalDate 的必要配置，由 jackson-datatype-jsr310 实现。

8. `defaultDateFormat(new SimpleDateFormat(CommonConstants.STANDARD_FORMAT))`
所有的日期格式都统一为以下的样式，即 yyyy-MM-dd HH:mm:ss

9. `addModule(new SimpleModule() ... )`
```java
mapper.addModule(new SimpleModule()
    .addSerializer(LocalDateTime.class,
        new LocalDateTimeSerializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")))   // 序列化时起作用
    .addDeserializer(LocalDateTime.class,
        new LocalDateTimeDeserializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")))); // 反序列化时起作用
```
对于 LocalDateTime 和 LocalDate 时间类型序列化时转换为 JSON 字符串时可以按照指定格式转换；
反序列化时也可以将指定的时间字符串类型转换为 LocalDateTime 和 LocalDate。

10. `serializationInclusion(JsonInclude.Include.NON_NULL)`
只针对非空的值进行序列化

### 封装Bean拷贝工具类


什么是Bean拷贝？

简而言之就是将一个对象的属性值拷贝到另一个对象的过程就叫Bean拷贝

为什么需要Bean拷贝？

一般讲，一个web项目通常有各种，很多种的数据类型，经常需要把一种数据类型转换成另一种数据类型，因此才需要用到Bean拷贝，需要Bean拷贝工具类来帮助我们更快的完成两个对象之间数据的拷贝（Bean拷贝）
