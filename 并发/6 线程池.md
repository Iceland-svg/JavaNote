## 1 为什么要用线程池

由于频繁创建销毁开销很大，所以提前把线程创建好放到池子里面
目的是提高效率

## 2 线程池的核心参数
### （1） int corepoolSize 

核心线程数

### 核心线程：

一创建就申请的线程
### 临时线程：

核心线程处理不过来了就申请一些其他线程来帮忙，帮忙的就是临时线程
不忙的时候就释放临时线程，但是核心线程永远不会销毁，除非销毁整个线程池

### （2） int maximumPoolSize

最大线程数

### （3） long KeepAliveTime

线程的存活时间

### （4） TimeUnit unit

线程允许休息的最大时间

### （5） BlockingQueue workQueue

#### 任务队列

里面放的都是线程要执行的任务，每个任务都是Runnable来描述的，使用线程池的时候，先会创建线程，然后需要调用者放一些任务，线程就会从任务队列里取出任务来执行

### （6） ThreadFactory threadFactory

#### 线程工厂类
统一管理线程创建
工厂模式的设计初衷是为了弥补构造方法的缺陷，因为在构造方法中，为满足不同构造需求可能会出现需要重载的情况，重载要求我们方法名字相同，参数列表不同，但是实际上就是可能会出现参数列表也相同的构造方法，所以我们不用构造方法，让这个类不包含构造方法，单独写一个工厂类，在内部写静态方法，这样可以实现不同名字不同参数列表的构造
 
代码案例

### （7） RejectedExecutionHandler handler

#### 拒绝策略
如果任务队列满了，我们又再次添加新任务，这时候按道理是会阻塞的，但是在实际情景中，对于某个程序，如果需要高时效性，这里绝对不能阻塞

### 四种拒绝策略

（1） AbortPolicy
直接终止
（2） CallerRunsPolicy
让调用者来执行任务，调用者也是一个线程
（3） DiscardOldestPolicy
丢弃掉最老的任务
（4） DiscardPolicy
丢弃掉最新的任务

## 3 ExecutorService使用

本质上也是工厂类，创建不同风格的线程池

```java
public class useOfExcutorService {  
    public static void main(String[] args){  
        //固定线程数目的线程池，核心线程数和最大线程数都是4  
        ExecutorService service1 = Executors.newFixedThreadPool(4);  
        //核心线程数为0，最大线程数为“int最大值"的线程池  
        ExecutorService service2 = Executors.newCachedThreadPool();  
        //固定 只有一个线程的线程池  
        ExecutorService service3 = Executors.newSingleThreadExecutor();  
        //本质上是计时器，在一定时间之后执行放到这个线程中的任务  
        ExecutorService service4 = Executors.newScheduledThreadPool(10);  
  
        for (int i = 0; i < 100; i++) {  
            //由于匿名内部类的变量捕获,局部变量必须是final或者effective final  
            //final修饰的实例变量必须在构造时就初始化  
            //final修饰的变量必须初始化，而且不能二次赋(修改)  
            //final修饰的类不能被继承  
            //final修饰的方法不能重写  
            //final修饰引用类型引用不能变  
            //以下技巧可帮助避免变量捕获  
            int id = i;  
            service1.submit(new Runnable() {  
                @Override  
                public void run() {  
                    //此处是任务  
                    System.out.println("执行一些任务"+id);  
                }  
            });  
        }  
    }  
}
```

## 4 自实现线程池

```java
public class MyFixedThreadPool {  
    private BlockingQueue<Runnable> queue = new LinkedBlockingQueue<Runnable>();  
    //由于是固定线程数的，这里给线程数参数n，  
    public MyFixedThreadPool(int n){  
        //刚开始初始化时，没有任何任务，所有线程全部阻塞，其实也就是先把线程都创建好了  
        for (int i = 0; i < n; i++){  
            //不断的获取任务去执行  
            Thread thread = new Thread(()->{  
                try {  
                    while (true){  
                        //Runnable类对象其实就是任务  
                        //由于这里的任务是封装好的，不是直接裸露出来的代码  
                        //我们需要调用run()来执行任务  
                        //同时这里也避免了为每个任务创建线程，实现线程复用  
                        Runnable task = queue.take();  
                        //没有任务就阻塞这个线程，等到其他线程submit  
                        //要记住阻塞只会在一个线程里，i仍会继续++  
                        task.run();  
                    }  
                } catch (InterruptedException e) {  
                    e.printStackTrace();  
                }  
            });  
            thread.start();  
        }  
    }  
    //submit在使用的时候其实就是利用匿名内部类在参数括号里写任务  
    public void submit(Runnable task) throws InterruptedException{  
        //放任务到任务队列  
        queue.put(task);  
    }  
}
```

测试代码

```java
public class useOfMyFixedThread {  
    public static void main(String[] args) throws InterruptedException {  
        //创建线程池  
        MyFixedThreadPool myFixedThreadPool = new MyFixedThreadPool(3);  
  
        //给线程池任务去执行的代码  
        for (int i = 0; i < 100; i++){  
            int id = i;  
            myFixedThreadPool.submit(()->{  
                System.out.println("执行任务"+id);  
            });  
        }  
    }  
}
```

## 线程池执行流程（核心）

当一个任务被提交给线程池时，流程如下：

1. 先看核心线程：如果当前运行的线程数 < corePoolSize，直接创建新的核心线程执行该任务（即使有核心线程空闲）。
2. 核心线程满了：如果当前线程数 ≥ corePoolSize，任务被放入工作队列（workQueue）等待。
3. 队列满了：如果队列已满，且当前线程数 < maximumPoolSize，创建非核心线程执行任务。
4. 达到最大线程数：如果线程数已达 max 且队列也满，执行拒绝策略。

## 用户态与内核态

### 概念解释

**内核态**：CPU 可以访问内存所有数据，包括外围设备（硬盘、网卡等），拥有最高权限[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。

**用户态**：只能受限访问内存，不允许访问外围设备，权限较低[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。

操作系统将 CPU 划分为两个权限等级：用户态（Ring 3）和内核态（Ring 0）[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。应用程序大部分时间运行在用户态，只有在需要操作系统提供服务时才会切换到内核态[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。

### 用户态与内核态的切换

当程序需要执行一些内核才能完成的操作时（如读取文件、网络通信等），需要通过**系统调用**从用户态切换到内核态[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。

切换过程包括[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)：

1. 用户态程序将参数放入寄存器或堆栈
    
2. 执行陷阱指令（Trap Instruction）
    
3. CPU 切换到内核态，执行操作系统指令
    
4. 系统调用完成后，重置为用户态并返回结果
    

**用户态和内核态的切换开销较大**，因为需要传递参数、保存和恢复寄存器状态等[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。

### 2.3 Java 线程与用户态/内核态的关系

Java 的线程是**映射到操作系统原生线程之上的**[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)。这意味着：

- Java 线程的创建、启动、阻塞、销毁等操作最终都需要**操作系统内核**的参与
    
- 每次线程操作都会涉及**用户态与内核态的切换**
    
- 这种切换会消耗大量系统资源[](https://cloud.tencent.cn/developer/article/2132128?from=15425&frompage=seopage#1)
    

实验中，创建并启动 10 万个线程耗时约 10.99 秒，而纯循环操作仅需 1 毫秒，差距巨大[](https://hanshuliang.blog.csdn.net/article/details/120202188#1_25)。这说明线程的创建和启动涉及内核操作，开销非常可观。

### 2.4 线程池如何减少内核态切换开销

从系统创建一个新线程，需要调用操作系统 API，由内核执行一系列操作——这就像"请银行柜员帮忙复印"，过程不可控、效率低[](https://developer.aliyun.com/article/1619284#1)。

而**从线程池获取线程**，整个过程是**纯用户态操作**——就像"自助复印"，完全由自己控制，效率更高[](https://developer.aliyun.com/article/1619284#1)。

线程池减少内核态切换开销的核心机制：

|对比|每次新建线程|使用线程池|
|---|---|---|
|操作性质|涉及用户态→内核态切换|纯用户态操作|
|线程创建|每次都要内核参与创建|预先创建好，复用|
|线程销毁|每次都要内核参与销毁|归还池中，不销毁|
|性能开销|大（系统调用开销）|小（用户态操作）|
